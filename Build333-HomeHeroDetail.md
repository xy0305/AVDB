# Build 333 — Home hero detail image (art.image + bottom gradient)

Base: Build 332 / `1f51964`, `feat/home-hero-color-332`. MARKETING 1.0.2, build 333. Branch `feat/home-hero-detail-333`. Unsigned IPA: `AVDB-unsigned-1.0.2-333-home-hero-detail.ipa` (CI artifact `AVDB-333-release`).

This build was planned jointly with Muse and Kai after the user installed Build 332 and reported 「没变」: the FNS-267 hero still showed the jacket floor's front window (a 398 px-wide slice upscaled to full screen, with visible blocky magenta artifacts), not the detail page's big image. The user's words: **「直接用详情页大图没加上，详情页大图底部渐变，按钮可以挡住小部分大图」** — use the detail page's big image itself; the detail big image graduates at the bottom; buttons may cover a small part of the big image. Asked how to treat the transition state, the user picked: **keep the jacket floor as the transition, swap the detail image in automatically when it arrives** (「保留封套地板过渡，详情图到了自动换上」).

## What was wrong in 332 (from the 333 survey of Build 332)

1. **The hero painted a different bitmap than the detail page.** 332's `HeroResolverSharp.primaryImage` returned `art.rawImage ?? art.image` — the uncropped original. The detail page's `portraitHero` paints `art.image`, the resolver's display image: for a PS winner the official portrait, for a jacket-sourced winner the colour-preserving front display raster. 332's reading of the user's 「直接拿原图」 as "the unprocessed original bitmap" was the misunderstanding; the user meant the detail page's big image itself.
2. **The winner is queued per item.** The enrich → resolver pipeline resolves current → +1 → −1 → … in order, so an item several positions in is still on its floor when first swiped to. On the floor, a jacket shows only its front window — correct per 331/332, but it is not the detail image, and a 398 px window upscaled ~3× shows blocky artifacts on real YCbCr jackets (the synthetic CI fixtures never showed this).
3. **The hero's bottom edge was hard-cut.** The light shortcuts sheet overlapped the hero by 32 pt with a straight edge; the detail page instead *graduates* the poster's bottom into the page background (gradient stops 0.36 → 1.0 into the tint) with the controls floating on the image.

## Locked plan (agreed with Kai and the user, implemented exactly)

1. **Sharp layer = the detail page's display image.** `HeroResolverSharp.primaryImage(from:)` returns `art.image`. Everything downstream is unchanged: the same candidate classification, HeroCoverDisk store/restore (which now stores and restores the display image), detail ↔ home winner sharing by movie id, keep/evict decided at result-arrival time. For a jacket-sourced winner the display raster is the `PosterColorCrop` front crop (colour-preserving since 332); `HomeAnchoredFill`'s display window is a no-op for it (it is already a portrait), so no double-windowing.
2. **Floor unchanged (user's pick).** The two-level jacket floor (cover first, thumb fallback, original bitmaps, display-time front window) stays as the transition state; the winner crossfades in automatically on arrival, exactly as 331/332.
3. **Detail-style bottom gradient.** The hero's `scrims` gain a second gradient: `Color(.systemBackground)` from opacity 0 at the top of a 56 pt band to full opacity exactly at the shortcuts sheet's top edge (hero height − `heroContentOverlap`), solid below — the image melts into the page background and the sheet seam disappears, in light and dark mode alike. The black legibility scrim hands off inside the band (its last stop reaches 0 at the sheet edge) so the fade can reach the true background colour. Bottom chrome rides above the band's strong region: dots bottom inset 16 → 46, text block (66 with dots / 50 without), 「更多」 button 8 → 38 (all plus the 32 pt overlap). Search button, 「看熱播」 chip, gestures, 328 vertical-swipe arbitration and 330 tap rules unchanged; faces (upper ~25–40 % of the hero) are untouched by the fade.
4. **Tests / packaging.** `HomeHero333Tests` (sharp layer is `art.image` itself for a PS-style artwork whose raw original differs; jacket-sourced winner paints the front display raster, not the envelope; eviction + disk restore returns the 745-wide display image, not the 1000-wide raw original; documented bottom insets). `scripts/test-home-hero333.py`; CI job `home-hero-333`; release regression list; `scripts/package-lut333.py`; artifacts `AVDB-333-*`. Prior 327–332 jobs stay. Marketing 1.0.2, build 333.

Out of scope (not touched): pipeline ordering / concurrency, floor rules, gesture redesign, search size, liquid-glass restyle, tab merge, live CoverSR, token refresh, AICover on the hero.
