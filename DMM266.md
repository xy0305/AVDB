Realtime / series / other floors are intentionally out of scope for this preview.

## Official adult declaration audit
User explicitly states age 26 and authorizes ordinary official self-declaration. Actual official age document at `https://www.dmm.co.jp/age_check/=/?rurl=...` has **no forms**; rendered affirmative anchor is labelled `18歳以上なので進む`. Its href equals `__NEXT_DATA__.props.pageProps.yesButtonLink`, using GET to `/age_check/=/declared=yes/?rurl=...`. Decoded rurl must be an allowlisted ranking URL above. No login, ID, KYC, captcha or region bypass permitted.

Actual new anonymous HTTP session observed: ranking 302 -> official age page 200 -> official declared=yes GET 302 -> video ranking 200. Official Set-Cookie metadata: `age_check_done`, domain `.dmm.co.jp`, path `/`, expiry approximately 30 days; actual Secure flag absent. Cookie value is neither logged nor hardcoded. HTTP final response is often an HTML application shell (not a verified N-row document), so shell alone is NOT live-source success. Browser-hydrated pages contain the ranked anchors; browser session is not copied into App.

## App transport and security
Default-off persistent adult authorization switch; no authorization means age-page requests cannot trigger a declaration. GET declaration allowed only after parsing the official age page and validating its exact rurl. Redirects are manual, at most eight, HTTPS only, exact official hosts and endpoint/query allowlist; account/login/other domains fail closed. Source URLSession is ephemeral, receives only source Set-Cookie, uses expiry/domain/path/secure matching and never forwards AVDB/115 headers. Cookies are memory-only, reused while valid and cleared on consent revocation. Expired sessions can undergo a fresh official declaration when authorization is still present. No secrets in logs.

Allowlisted video hosts/paths:
- `/av/ranking/` with content terms daily|weekly|monthly, or monthly+type=actress
- `/av/content/?id=<cid>` for manufacturer verification
- `/av/list/?actress=<numeric-id>` as actress ranking destinations (not scraped for AVDB ids)

## Native preview and matching
Content parser requires the full continuum `1...expectedCount` in one document, preserves source order and unknown/unmatched slots; no inferred page URLs. Detail reads use authoritative tr/th/td `メーカー品番`, verifying `配信品番` matches requested CID. No CID prefix stripping/zero deletion. At most two detail requests; inflight dedup, bounded 24h public metadata cache, generation cancellation. AVDB movie mapping uses existing account/backend-scoped exact unique resolver; original JavDBImage and actual Movie.id -> existing MovieDetailView/115 path.

Actress parser requires ranks `1...100` with `/av/list/?actress=<digits>` links and a visible name; duplicate actress ids or conflicting names fail closed. AVDB actor mapping uses `ExternalActorIdentity` + `ExternalActorResolver` exact-name resolution only; **never invents actor IDs**. Ambiguous/incomplete results stay as source slots with honest unmatched status and optional manual candidate links to `ActorDetailView`.

HTML import remains intentional fallback, explicitly labelled user-imported and not live. Fixtures are neutral reconstructions or detail excerpts, not live documents. UI runtime fixture test validates native weekly import -> exact mapped movie -> detail boundary.
