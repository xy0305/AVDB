## Baseline and delivery boundary
Dedicated `feat/dmm-ranking-terms-from266` from `feat/dmm-ranking-from261`. Version remains 1.0.2 (266). Existing MediaPipe/Metal pipeline retained. Does not merge Tangxin build265 worktrees.

## Official ranking surface (audited 2026-10-27 from video.dmm.co.jp ranking JS)
Content boards on `https://video.dmm.co.jp/av/ranking/`:
- `?term=daily` → **20** rows (`【毎日更新】日間作品ランキング`)
- `?term=weekly` → **100** rows
- `?term=monthly` → **100** rows

Actress board (AV floor):
- `?term=monthly&type=actress` → **100** rows (`【100位まで】月間AV女優ランキング`)
- Official routing accepts `type=actress|series` **only** with `term=monthly`. Weekly/daily actress URLs are rejected.

Realtime / series / other floors are intentionally out of scope for this preview.

## Official adult declaration audit

Its href equals `__NEXT_DATA__.props.pageProps.yesButtonLink`, using GET to `/age_check/=/declared=yes/?rurl=...`. Localized `/en/age_check/=/` wrappers are accepted only when the decoded rurl remains an allowlisted ranking/content URL. No login, ID, KYC, captcha or region bypass permitted.

HTTP final response is often an HTML application shell (not a verified N-row document), so shell alone is NOT live-source success. Browser-hydrated pages contain the ranked anchors; Safari session is not copied into App.

## Automatic refresh (no HTML import required)
In-app **刷新榜单** order after adult authorization is on:

1. **WKWebView silent hydrate (primary)** — hidden non-persistent `WKWebView` loads the allowlisted ranking URL, completes the official declaration when authorized, waits until ranked DOM matches `expectedCount`, then feeds `outerHTML` into `DMMRankingCore`. Navigation outside the host/path allowlist (including accounts/login) fails closed.
2. **GraphQL secondary** — verified read-only POST to `https://api.video.dmm.co.jp/graphql`:
   - Content: `ppvContentRanking(limit, offset, filter: {daily|weekly|monthly: {floor: AV}})`
   - Actress: `ppvActressRanking(limit, offset, filter: {monthly: {floor: AV}})`
   - Introspection is disabled (`extension.datadogTracer... introspection disabled`). Only the field shapes above were confirmed live (2026-10-27). Incomplete/error payloads surface as `LIVE_*_BLOCKED` / honest empty state — never synthetic rows.
3. **URLSession document** — existing ephemeral cookie transport (usually shell-only).
4. **Import HTML** — intentional manual fallback only; labelled user-imported and not live.

## App transport and security
Default-off persistent adult authorization switch; no authorization means age-page requests cannot trigger a declaration and automatic refresh refuses to run. GET declaration allowed only after parsing the official age page and validating its exact rurl. Redirects are manual, at most eight, HTTPS only, exact official hosts and endpoint/query allowlist; account/login/other domains fail closed. Source URLSession is ephemeral, receives only source Set-Cookie, uses expiry/domain/path/secure matching and never forwards AVDB/115 headers. WKWebView uses `WKWebsiteDataStore.nonPersistent()`. Cookies are memory-only, reused while valid and cleared on consent revocation. Expired sessions can undergo a fresh official declaration when authorization is still present. No secrets in logs.

Allowlisted video hosts/paths:
- `/av/ranking/` with content terms daily|weekly|monthly, or monthly+type=actress
- `/av/content/?id=<cid>` for manufacturer verification
- `/av/list/?actress=<numeric-id>` as actress ranking destinations (not scraped for AVDB ids)
- GraphQL host fixed to `api.video.dmm.co.jp/graphql` (POST JSON only)

## Native preview and matching
Content parser requires the full continuum `1...expectedCount` in one document, preserves source order and unknown/unmatched slots; no inferred page URLs. After a content board loads, official GraphQL `ppvContent.makerContentId` fills manufacturer evidence (never derived from CID). Detail reads still use authoritative tr/th/td `メーカー品番`, verifying `配信品番` matches requested CID. No CID prefix stripping/zero deletion. At most two detail requests; inflight dedup, bounded 24h public metadata cache, generation cancellation. AVDB movie mapping uses existing account/backend-scoped exact unique resolver; original JavDBImage and actual Movie.id -> existing MovieDetailView/115 path.

Actress parser requires ranks `1...100` with `/av/list/?actress=<digits>` links and a visible name; duplicate actress ids or conflicting names fail closed. AVDB actor mapping uses `ExternalActorIdentity` + `ExternalActorResolver` exact-name resolution only; **never invents actor IDs**. Ambiguous/incomplete results stay as source slots with honest unmatched status and optional manual candidate links to `ActorDetailView`. GraphQL actress boards use the same exact-name mapper.

HTML import remains intentional fallback, explicitly labelled user-imported and not live. Fixtures are neutral reconstructions or detail excerpts, not live documents. UI runtime fixture test validates native weekly import -> exact mapped movie -> detail boundary.
