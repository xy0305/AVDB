# Build 331 — Home hero front crop (no more jacket "collage")

Base: Build 330 / `0c1a02b`, `feat/home-chrome-330`. MARKETING 1.0.2, build 331. Branch `feat/home-hero-crop-331`. Unsigned IPA: `AVDB-unsigned-1.0.2-331-home-hero-crop.ipa` (CI artifact `AVDB-331-release`).

This build was planned jointly with Muse and Kai after the user installed Build 330 and reported that most home hero pages showed the wide DVD jacket (back cover + spine + front side by side) instead of the single-person front portrait the iPhone detail page shows.

## Root causes (from the 331 survey of Build 330)

1. **Landscape layers were painted raw.** The ranking DTO `cover_url` is an 840×568 jacket (back cover left, front right). The 330 floor (`startFloorLoad` / `HomeHeroPage.task`) and the 330 middle step (`loadEnrichCover`) used `ImageLoader.load` without the `FrontPosterPolicy` crop, and `HomeAnchoredFill` centered the jacket horizontally — the visible window was the back cover's right part, the spine and ~70 % of the front: the collage. The middle-step condition (`isNewCover || cover != dtoThumb`) was always true, so it reloaded the same jacket. The 330 test enshrined this with portrait fixtures.
2. **Sharp bitmaps were dropped and never restored.** `keepBitmaps` was frozen at enqueue time (current ±1 only), and eviction cleared `sharpImage` but kept tier / width / phase. On swipe-back, `applySharp`'s metadata-only guard (`tier == && width >= && finalized → return`) refused to put the bitmap back, and `shouldRetry` refused to rerun finalized A/B items, so the page sat on the jacket for the whole session.
3. **The resolver started late.** `enrichHeroCIDs` enriched all ≤10 items sequentially (30 s detail timeout + catalogue lookup each) and the resolver was gated on the whole batch.
4. **`setCurrentIndex(_, movies:)` overwrote enrich-merged movies with raw DTOs** (no type / actors / catalogue metadata), changing the `DetailPosterResolver` identity and — for labels outside the censored list — turning off DMM rules and the jacket crop.
5. **Detail ↔ home winner sharing missed.** The detail cache key includes the full movie record, so the detail page's full record and the hero's ranking record never met; `HeroCoverDisk` readbacks were thrown away by cause 2.

## Locked plan (agreed with Kai, implemented exactly)

1. **Invariant.** No hero layer — including the ambient wash — ever draws an uncropped landscape image. All hero painting goes through `ImageLoader.loadPoster` (the `FrontPosterPolicy.cropRect` crop-or-passthrough chain the rails use). The ambient colour is sampled from the currently displayed (cropped) bitmap; there is no separate full-jacket fetch. `HomeAnchoredFill` right-anchors any residual landscape raster only as a safety net (`HeroFillAnchor`).
2. **Two-level floor.** Level 1 = the sharpest image in the movie's current record, painted sharp: front-cropped `cover_url` preferred, thumb fallback (portrait beats landscape, then width). Parallel race only for current ±1 — first arrival paints, a later sharper one replaces it; elsewhere cover first, thumb on failure. The floor re-evaluates automatically when enrich merges a better cover. The 330 middle step (`enrichImage`) is removed. Level 2 = the `DetailPosterResolver` winner (same as the iPhone detail `portraitHero`), which overrides the floor on arrival with absolute priority. Cross-fade ≤ 0.45 s as before.
3. **Bitmap lifecycle.** Sharp state = winner URL finalized **and** bitmap retrievable from memory or `HeroCoverDisk`. Keep/evict is decided by distance from the current index when the result arrives, not at enqueue. The winner is written to `HeroCoverDisk` under a winner-URL key (`hero-winner-331#NUMBER#URL#2048`, encoded off the main actor). Swiping back to an evicted item restores only from `HeroCoverDisk` by winner URL: no resolver rerun, zero network requests. `applySharp` never assumes a sharp state when the bitmap is missing; an unretrievable result is not recorded as sharp.
4. **Field-level merge by movie id** (`Movie.preservingHeroEnrichment`): non-empty enriched cover / thumb / actors / type / CID-bearing catalogue metadata are never overwritten by a raw ranking DTO; rank / title etc. follow the latest ranking.
5. **Per-item pipeline enrich → resolver.** Order current → +1 → −1 → +2 → −2 → … over the full cap-10 list; concurrency cap 2 (priority gates re-rank waiters on every swipe); 8 s per-item enrich budget with the login token (as detail requires); that item's resolver starts as soon as its own enrich finishes. The 6 s mark stays a floor-display rhythm point and never cancels in-flight work. Items whose enrich timed out / failed are retried once when they become current. CID check (verified): the v4 detail response carries no CID field (cover / thumb / preview images are on the JavDB CDN), so the home pipeline now fetches the native detail (`movieDetail(_, catalogue: false)`) and runs the avbase catalogue lookup only when no DMM CID is already known for the record.
6. **Bidirectional winner sharing by movie id.** `DetailPosterWinners` (memory, keyed by account scope + movie id + enhance tag + cache version) is written by every `DetailPosterResolver.resolve`; `initialLayout` and `resolveShared` consult it, so the detail page's full record finds a winner the hero resolved and vice versa. `HeroCoverDisk` is the persistent layer. Returning from detail upgrades the hero immediately via `.detailPosterWinnerResolved`.
7. **Tests.** `HomeHero331Tests` (UITests/DetailPosterQualityTests.swift): cold-start ABF-398-like fixture first frame is the front portrait, not the collage; swipe to item 4 and back keeps the official winner (no jacket, no low-res floor posing as final); offline cold start with cache shows the detail winner directly; landscape fixture 840×568 cover + 166×236 thumb never shows an uncropped layer and the floor uses the 398×568 crop; network off with the resolver never completing stays on the sharp front floor; evict then swipe back restores with zero network requests and no resolver rerun; setCurrentIndex keeps merged fields; winner shared by movie id. `test330EnrichMergedDetailCoverIsMiddleStep` now asserts the two-level semantics. `scripts/test-home-hero331.py` holds the static contracts; CI job `home-hero-331`; release regression list updated; `scripts/package-lut331.py`; artifacts `AVDB-331-*`.

Out of scope (not touched): gesture arbitration, search 44 pt, tap hit-testing, liquid-glass shortcuts, light home, 3-column grids and 換一組, tab bar, tab merge, live CoverSR, token refresh, 403-as-auth, 327 failure-page seed. No AICover on the hero.

Hosted unit tests set `HeroCoverStore.suspendAppCallsForTests` (DEBUG only) so the host app's HomeView stops driving the shared store while a test owns it.
