## Implemented flows

1. Unified JRPolicy exact identities accept complete R18-292, numeric-leading amateur numbers such as 723GGH-009 and 200GANA-3000, and retain the original FC2 behavior. The numeric prefix is not removed in global matching/caches. The studio/serial separator is retained for mixed letter+digit labels, so R18-292 cannot collide with R1-8292. CatalogueIdentity has a separate source-specific key and only permits a missing leading numeric namespace when avbase's candidate group is unique. Different nonempty numeric namespaces never compare equal. Movie.codePrefix preserves R18/723GGH instead of R/GGH, including when the server supplies a truncated number_letter.
2. Both native JavDB detail APIs call optional enrichment. Missing title, description, date, duration, actor display names, maker, publisher, series and artwork are filled from a verified record. Populated primary fields, JavDB ID, number, catalog type, structured actor IDs, links, recommendations, favorites and playback identifiers are not replaced or fabricated. Existing primary desc is not hidden by a newly filled summary.
3. avbase uses only public `https://www.avbase.net/works?q=...` HTML and exactly one inert __NEXT_DATA__ JSON block. Search records contain usable metadata; a successful detail-page fetch is not required or claimed. Exact work identity is preferred, namespace duplicates need unique product or canonical evidence, fuzzy first-hit selection is prohibited. Source URLs use the actual prefix:work_id canonical identity. No /api probing or browser state is used.
4. DMM amateur can be read directly when Movie.originalURL already supplies a validated amateur content URL and compatible actual CID, or via an exact avbase record's linked amateur product. CIDs are read from source links and matched to product_id, never constructed by padding or stripping the requested number. The independently authored minimal read-only GraphQL request uses https://api.video.dmm.co.jp/graphql. Null/missing largeUrl and mediumUrl are tolerated; either actual image can supply both poster/cover roles. CID, directory, filename, host and digital/amateur versus digital/video versus mono/movie namespace must agree. Samples and unrelated photos cannot become package images.
5. Bound source images enter the existing real-image decode/quality/selection path. Immutable navigation seeds also discover source images where there is no Tenhow actor path, avoiding a seed that silently bypasses the new provider. Existing six-attempt/two-image-worker/twelve-second selection budgets, Tenhow/Amazon reserved opportunities, JavBus and TPDB handling remain intact. Amateur jp.jpg and MGS h1 images are not treated as DVD jackets. No low-resolution source is enlarged or declared HQ. Guessed CoverURLBuilder CIDs are explicitly disabled for digit-bearing prefixes.
6. Optional transport is ephemeral, cookie/credential/cache-free, HTTPS-only, no-redirect, MIME/status/size bounded, cancellation-aware and memory-only cached (128 entries; 1-hour positive/5-minute negative). Metadata budget is 4 seconds by default and 6 seconds maximum. Authentication/age/WAF/HTTP/schema failures leave the existing JavDB movie intact. Account changes during an SDK await cancel publication.

## Regression evidence and limits

- `scripts/test-catalogue-metadata.py` contains neutral fixtures executing the production identity, HTML/JSON, package-image and Movie-merge code on a Swift-capable host. Cases include R18/full-width input, numeric-leading labels, conflicting namespaces, duplicate Next data, duplicate work namespaces, exact product binding, wrong CID/host/counter/sample, null/missing image fields, GraphQL errors/null content, preserved populated fields and preserved JavDB IDs/types.
- The release workflow runs this native test. Existing standalone native-ranking and mapping harnesses now include the new production parser dependency rather than substituting its behavior.
- Local iSH has no Swift compiler. Local source/static integration checks, existing poster/source static regressions and git diff --check passed; native assertions and complete iOS compilation are NOT claimed locally. The parent build219 Release CI must validate them.
- This adds enrichment to existing real JavDB movie routes, not a standalone avbase/DMM search catalog or synthetic JavDB identity. A title absent from JavDB cannot be opened using a fabricated movie ID. List-only records do not trigger background per-card provider scraping.
- Only evidenced DMM/MGS package image hosts and paths are admitted. Arbitrary avbase CDN providers, trailers, sample galleries, all Amane sources, suffix editions and all filename extraction grammars are not claimed. R18 compact strings without an explicit prefix separator are deliberately rejected as ambiguous; FC2/Western rules are retained.
- Provider availability, geographic restrictions and image resolutions remain external constraints. Failure is optional/fail-closed, not a success placeholder.
