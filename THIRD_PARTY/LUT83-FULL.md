# Full desktop83 mobile numerical mode (Build 268)

The user supplied a desktop LUT v8.3 archive for analysis. Its redistribution license is not confirmed. The new `Desktop83` namespace is an independent implementation of the documented numerical operations, constants, target ranges and template search. The Python GUI, installer, subprocess commands, desktop paths, Lua implementation and uploaded prose are NOT bundled or executed. Existing v6.7.5/267 notices and their license caveats remain in place. This does not grant a license to upstream material.

Two modes are intentionally distinct:

* **267 protection** retains the existing OriginalLUT engine, neutral/high-match identity policy, near-white handling and bounded safety search. The original engine prefix remains byte-for-byte unchanged.
* **v8.3 original numerical mode** uses desktop 0.67 brightness, 0.57 contrast, 0.82 saturation, 0.92 pushed-overexposure protection and the standard/high-match/extreme-dark templates. Analysis and final cube export have different overexposure guards exactly as specified in the reviewed numerical functions. Seven deterministic neutral sample groups compare with an isolated oracle made only from reviewed pure Python numerical functions; the uploaded script is never executed wholesale.

Mobile equivalences are not pixel-identical desktop pipelines. Local video analysis samples at most 24 timestamps over the middle 90%, maximum 640-pixel long side, with cancellation/progress and a 20-second acquisition deadline. Decoded-frame accumulation uses eight already decoded frames with at least 0.8-second separation and a 15-second deadline; HLS composition and HDR remain unsupported. No new media downloading or network adapter is added.

The existing pinned MediaPipe Tasks Vision 0.10.14 model is used. On physical iOS devices creation and VIDEO inference use GPU on one dedicated OS thread for the app lifetime. Simulator builds use the real model's CPU delegate because the old Metal delegate is not a reliable simulator target. No fake landmark stub is substituted. Generated neutral color-block tests do not establish real-face accuracy or physical GPU correctness. Absence of a detected face falls back explicitly to threshold segmentation; the desktop detector-present/no-face branch instead skips the frame. The independent mobile segmentation includes YCbCr+HSV thresholds, ellipse opening/closing and eight-connected component geometry/position/area scoring on a half-resolution grid, not OpenCV's exact integer raster/morphology. Deterministic thinning replaces random NumPy sampling. Color statistics and comparison labels disclose their ROI/sample scope.

Local images/videos are selected with the system importer. Image thumbnails, preview frames (maximum 10), and sample statistics stay in memory until reset/detach. Exported cubes/presets contain transforms, not source photographs. Directory enumeration is restricted to explicitly granted folders with bounded entry/queue counts. Batch outputs remain temporary until explicitly shared/saved by the user. Presets use SHA256 URL keys without persisting the original URL, and offer per-item/universal deletion and a clear-all action.

3D CUBE import is bounded to 24 MiB and dimensions 2...65, validates finite in-range RGB data, counts, nonduplicated size/domain declarations, and finite nonsingular domains. Non-unit domains are normalized in nonlinear SDR sRGB. 1D/mixed/HDR/out-of-range cubes are rejected rather than guessed. Imports preserve the actual cube. Recognized seven-parameter desktop comment recipes can be edited by regenerating a parameter cube; arbitrary cubes without a recipe are not falsely reverse-engineered. Exports include parameter/mode comments, real dimensions/domain and red-fastest indexing. Safe-mode 65 cubes resample its applied 33 lattice; desktop83 65 cubes are baked directly. Strength dissolve, sharpening and debanding are not baked into .cube exports, and the preview explicitly states that it shows LUT only.

MPV installation, Python pip installers, global desktop Lua installation, Windows process handling, arbitrary shell execution, subtitle file repair and a replacement player are not ported. Native apply/preview, share/save-to-Files, local presets and native enable/disable controls provide the applicable equivalents. No adult source adapters, parsing/filtering/network code, 115 parameters, subtitles, progress-tap seek or other player gestures are changed. KSPlayer and other inherited dependency/license obligations remain unchanged.
