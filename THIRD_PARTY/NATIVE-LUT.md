# Native LUT (original numeric engine)

Adapted from supplied `网页视频实时 LUT（v6.7.8）`, original metadata `@author You`, `@version 6.7.8`; complete unexecuted source in `THIRD_PARTY/lut-v6.7.8.txt`. Prior baseline `THIRD_PARTY/lut-v6.7.5.txt` retained for provenance. No license was present in that source. Redistribution permission has not been independently verified; no license is invented for it.

`AVDB/Resources/OriginalLUT.js` reuses the complete original pure numeric section from v6.7.8: CONFIG, calibrated TARGETS (incl. standard R/B 1.24–1.50 / luma 0.35–0.54 / sat 0.22–0.34), templates with tint +6, tightened adjust ranges, cold-scene high-match protection, extreme-dark thresholds (luma <0.28, hl <0.01, sh >0.24), `_balanceParamStrength` (skip bright-comp / temp-floor / standard bright floor), staged `predictParams` (conservative scene, bright-search clamp, R/B 60% target, contrast↔temp order in apply/cube), saturation scalar 0.82, and `generateLutData` pipeline order matching the userscript. Sampling reuses original capture post-landmark body, dynamic Cr quantiles, skin rejection, high-RB/high-pixel statistics, global highlight ratio and minimum 150-skin-pixel rejection. Bounded multi-frame analysis (userscript v6.7.8 + build 274 stability): native grab loop takes up to 3 decoded frames ≈**120ms** apart while playing (paused → single frame; no seek), early-stops on a MediaPipe face box, prefers face-box frames over 中央50%. **Scene-change guard**: if per-frame `skin_lum` span > 0.08 or `skin_rb` span > 0.18, do not median mixed scenes — keep the largest coherent cluster (or best single face/center frame) via `selectCoherentPairs`. Otherwise median of per-frame skin stats (`skin_rb/rg/lum/sat`, `full_contrast`, `full_sh_ratio`), keep the first selected frame's `full_hl_ratio` / high-RB, merge skin pixels, then max-3000 + coarse-400 deterministic subsampling into `predictParams`. First **开启** waits ≈**400ms** before grab (avoid black/loading); 重新分析 stays immediate. After analysis publish, native CIColorCube / online Metal filter **crossfades ≈200ms** (old→new or original→new); 关闭/bypass clears immediately. `analyzeFrame` remains the single-frame entry for parity tests; `analyzeMultiFrame` is the multi-frame aggregator. High-match routing matches v6.7.8 (classifiers only; forceHighMatch / condFace backdoors removed). No DOM, MediaPipe loader, WebGL, network, CORS patches or userscript init is evaluated. Each invocation owns an isolated JavaScriptCore context; analysis executes on the detached background worker. CoreImage receives original RGB cube expanded to RGBA Float32, in sRGB.

Face ROI uses official MediaPipe Tasks Vision 0.10.14 FaceLandmarker (GPU, VIDEO, float16/1 bundled model) with **first-face ALL landmark min/max extrema** and `faceBoxExpand=1.0` — same contract as the userscript. Desktop MPV uses IMAGE mode and raw int(min/max); expand 1.0 keeps equivalent box extents modulo 1px floor/ceil. Browser WebGL vs native Metal GPU, VIDEO tracker history and AVFoundation decode may still differ; ROI geometry given identical landmarks is shared (`OriginalLandmarkGeometry`). Fallback without a face remains 中央50%.

Supported scope: composable SDR AVPlayer assets, plus online/HLS SDR via `NativeHLSLUTSurface` (same-clock Metal presentation; AVPlayerLayer fallback; no AVVideoComposition on HLS). Brief decode/GPU gaps keep the last Metal frame visible (≈2s stall grace) instead of flickering to the original layer; hard fallback remains for HDR/DRM/PiP/AirPlay/background and true long stalls. `forceCopy` after 开启 / seek / bypass-clear / filter publish so resume does not depend on a stale `hasNewPixelBuffer` edge. PQ/HLG HDR and protected content stay on original. No cloud writes. Remote composition, orientation and visual color fidelity require device testing; compilation and numeric parity are not end-to-end runtime validation.

`scripts/test-native-lut.py` evaluates numeric functions from the supplied full v6.7.8 source in Node against `OriginalLUT.js`: `sampleSkinStats` / classifiers stay exact; **Build 278** requires `predictParams` to equal the 6.7.8 oracle whenever the 6.7.8 bake already passes the per-frame safety check, and only diverges when the safety gate must nudge. Cube equality vs the oracle is asserted outside the shadow toe and below the highlight-shoulder knee. Below toeEnd the toe contract applies (black point 0, source hue, bounded slope). cubeRGBA matches `generateLutData` for port params; plus `analyzeMultiFrame` median / scene-guard. macOS CI additionally invokes the bundled JavaScript via native JavaScriptCore (1e-7). Linux only executes Node.

Deliberately not transplanted: userscript CORS/src hijacks, 115vod DOM/WebGL overlay, desktop Tk/MPV/Python tray (R/F hotkeys map to in-app 重新分析 / 关闭·重置), requestVideoFrameCallback scheduling, dependency installers. Multi-frame grab is native-bounded (≤3 / ~120ms / no seek; ~400ms first-enable delay); it is not a full browser RVFC loop. Cube crossfade is native UX only.

**Build 278** restores the 6.7.8 enhancement as the target look. Earlier Build 276 treated whos.tv stills as graded targets and damped params toward neutral; those stills are raw source frames, so that damping was wrong. Build 278:

- keeps the 6.7.8 `TARGETS` / templates / search (removes `gradedRef` damping and the Build 275 permanent washout hard-caps)
- adds a shadow toe in `generateLutData` (source hue, black point 0, slope 0.97–1.60) so dark fabric / stockings keep detail under high contrast/shadow
- softens the baked highlight shoulder (`knee=0.78`, `ceil=0.97`) instead of the hard 0.92 plateau
- runs a per-frame safety gate after `predictParams` that only nudges params when the full bake would crush near-black, blow highlights, push skin magenta, or oversaturate

On a ~10k-frame whos.tv source-still benchmark, 278 keeps ~91% of 6.7.8 mean ΔRGB while collapsing any-fail from ~77% → <1%. See `Build278-LUT-WhosTV-Big.md`. **Build 279** fixes the on-device haze reported on 278: the HLS/Metal surface (and its analysis copy) built `CIImage(cvPixelBuffer:)` without a colour space, so CoreImage applied the buffer's BT.709 transfer → sRGB conversion and lifted every shadow; decoded SDR buffers are now tagged sRGB so neutral Metal equals the AVPlayerLayer picture (CI host check `sourceImageIdentityToDecodedBuffer`). The bake adds a white anchor (bright neutral source keeps its luminance), caps the toe slope at 1.10, and the per-frame gate adds lift / haze / grey-white / high-key / pink checks. See `Build279-LUT-HLS-Haze.md`.
