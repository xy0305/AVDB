# Build 332 — Home hero color (original bitmap + bottom overlap)

Base: Build 331 / `aea74b2`, `feat/home-hero-crop-331`. MARKETING 1.0.2, build 332. Branch `feat/home-hero-color-332`. Unsigned IPA: `AVDB-unsigned-1.0.2-332-home-hero-color.ipa` (CI artifact `AVDB-332-release`).

This build was planned jointly with Muse and Kai after the user installed Build 331 and reported that the home hero of SNOS-484 looked purple / grey / cooler than the same official poster on the detail page, even though the composition now matched. The user then asked to **use the original image** and **move the lower content up a little so it covers the bottom edge of the poster** (`直接拿原图`, `把下面的内容往上移一点，遮挡部分海报`).

## Root cause (from the 332 survey of Build 331)

The 331 crop *geometry* was correct — typography landmarks aligned with the iPhone detail `portraitHero` at NCC 0.983–0.998. There is no leftover 328 dim, no `colorMultiply`, and no blurred ambient sitting on top of the poster. Mid-band luminance was essentially unchanged (ΔL ≈ −0.15). The shift was chromatic: lose yellow (b* down ~5–7), skin picks up magenta (a* up ~1.4–3.3), and the S1 red goes dull pink (182, 90, 120 vs 221, 25, 46).

That is what happens when the home hero paints a **profile-stripped or block-cropped bitmap** rather than the same color-managed official poster the detail page draws:

1. **`CGImage.cropping(to:)` on a JPEG jacket.** 331's floor went through `ImageLoader.loadPoster`, which sliced the encoded JPEG with `cg.cropping(to:)`. JPEG color is stored in blocks; a raw slice, then upsampled to fill the hero, shifts skin and saturated reds toward magenta / grey. The detail page paints the complete official poster and never takes this path.
2. **`HeroCoverDisk` JPEG (quality 0.88) could drop the ICC.** A restore / relaunch then displayed sRGB values as DeviceRGB or Display P3, which on a P3 iPhone desaturates reds and cools warm skin. The current page may still have held the in-memory winner, but most cold or evicted pages did not.

These can stack: the jacket floor first (wrong grade), then a profile-stripped official winner (still wrong). Ken Burns + `.interpolation(.high)` explain only a mild softness, not the purple.

## Locked plan (agreed with Kai and the user, implemented exactly)

1. **Hero main layer paints the loader's decoded original bitmap with zero pixel reprocessing**, for both the two-level floor (cover first, thumb fallback) and the `DetailPosterResolver` winner (`art.rawImage`). No `CGImage.crop`, no `loadPoster` crop, no new bitmap for the hero. 331 priority, keep/evict, and detail ↔ home sharing stay.
2. **Landscape jackets are shown only via a display-time window** equal to `FrontPosterPolicy.cropRect` (same origin and size), implemented with view-level scale / offset / clip (`HeroFrontWindow` / `HomeAnchoredFill`). Jacket detection stays on the existing FrontPosterPolicy thresholds (aspect 1.35–1.65 and type). Non-jacket images keep the existing passthrough / fill. Ambient is still a wash *behind* the sharp layer, sampled from the currently displayed (front) region; it does not change sharp-layer pixels. The 331 invariant is rewritten in mechanism only: the hero paints the original image; the visible window is the front region only. Purpose unchanged: no layer may show the back-cover collage.
3. **Lower content overlap.** The light shortcuts / rails block moves up a fixed **32 pt** (chosen inside the agreed 24–40 pt window after a SNOS-484 layout check: faces sit around 25–40 % of the hero height, well above the bottom 7 %). This covers the hero's bottom edge. Hero bottom UI (title, date, dots, 「更多」) bottom insets increase by the same 32 pt and stay fully visible and tappable. The top-left 「看熱播」chip is unchanged (it is not a bottom inset). The overlap band is *not* in the hero gesture hit area. 328/330 vertical-swipe arbitration, gestures, and tap rules stay.
4. **Secondary, same build:** `loadPoster` and resolver pixel-crop sites switch to a source-image translate-redraw into a tightly packed sRGB 32 bpp bitmap (`PosterColorCrop`), preserving scale / orientation. The function never takes a `cg.cropping()` subimage as input — it translates the uncropped original into a context sized to the crop rect (translate −origin). Redraw only when a crop actually happens; native portrait passthrough stays zero-copy; results go into the existing cache. No filters, LUTs, or manual color correction. The hero no longer uses `loadPoster` cropping, so the two paths stay separate. `HeroCoverDisk` / `HQPosterDiskCache` JPEG (quality 0.88) preserves the ICC / color space (`PosterJPEGColor`) so a restore cannot drop the profile and display sRGB as DeviceRGB / P3.
5. **Keep `.interpolation(.high)`** on the hero — it now scales a pristine decoded image.
6. **Tests / packaging.** `HomeHero332Tests` (SNOS-484 and ABF-398-style fixtures, floor and winner states, render-level mean ΔE < 2 vs a reference `Image(uiImage:)` of the same CGImage with no magenta bias, visible window hides the back cover including a 1.65 critical-aspect fixture, floor → winner crossfade does not shift color temperature, overlap keeps bottom UI and faces visible, `loadPoster` tightly packed 32 bpp sRGB with ΔE < 2, ICC-preserving JPEG). `scripts/test-home-hero332.py`; CI job `home-hero-332`; release regression list; `scripts/package-lut332.py`; artifacts `AVDB-332-*`. Prior 327–331 jobs stay. Marketing 1.0.2, build 332.

Out of scope (not touched): gesture redesign, search size, tap hit-testing beyond excluding the overlap band from hero gestures, liquid-glass restyle, tab merge, live CoverSR, token refresh, 403-as-auth, 327 failure-page seed, AICover on the hero, sending CI to Kai.
